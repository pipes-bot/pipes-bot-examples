# mini-crm Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `mini-crm/`, a standalone WhatsApp CRM (BYON v2) with a fixed pipeline, an inbox that sends replies through pipes.bot, MCP-created drafts, and a built-in MCP server protected by Better Auth's OAuth provider, so Claude or another MCP client can read and update the CRM.

**Architecture:** A Vite + TanStack Router SPA talks to Convex. `POST /webhooks/pipes` verifies Standard Webhooks signatures and calls one transactional `ingest` mutation (copied from `conversation-analyzer` and adapted) that projects events into contacts, messages and activities. One internal send pipeline (`sending.ts`) serves the inbox, MCP direct mode and draft approval. `POST /mcp` is an `httpAction` that validates an OAuth JWT, resolves the workspace, and runs a per-request stateless `McpServer` whose tools call the same internal functions the UI uses.

**Tech Stack:** Node 22, pnpm 11, TypeScript ~7.0.2, Vite 8 + `@vitejs/plugin-react` 6, `@tanstack/react-router` 1.170 + `@tanstack/router-plugin` 1.168, Tailwind v4 + shadcn/ui (radix, nova preset), Convex 1.49.0, `@convex-dev/better-auth` 0.12.6 (local install), `better-auth` 1.6.33 + `@better-auth/oauth-provider` 1.6.33, `@modelcontextprotocol/sdk` 1.32.2, zod 4, Vitest 4 + `convex-test` 0.0.66 + `@edge-runtime/vm`.

**Spec:** `docs/superpowers/specs/2026-11-01-mini-crm-design.md`

**Reference code:** `conversation-analyzer/` (same repo) — copy and adapt, never import from it. The spike report quoted under Task 4 is the source for the OAuth config.

- Every public function resolves the caller's workspace and treats another workspace's resources as not found; every MCP tool does the same with `principal.workspaceId`.

## Review Focus

1. **A draft approved twice** (double-click, two tabs, or UI + retry): exactly one message is sent; the second call gets "Draft is no longer pending". Pinned in Task 8 (`approve twice sends once`).
2. **An app revoked in Settings whose JWT has not expired yet** (access tokens live 1 h and are verified offline): the next `/mcp` call returns 401 because `authenticateMcpRequest` also requires a live consent for `(sub, azp)`. Pinned in Task 4 (`no consent → 401`) and in the OAuth smoke (Task 14).
3. **A conversation started from the phone** (an echo to someone who never wrote): the contact is created as `lead` with no `lastInboundAt`, so the window is closed and the inbox explains why instead of letting a send fail at Meta. Pinned in Task 5 (`echo to unknown recipient creates a closed-window lead`).
4. **A contact whose last number is gone** (demo reset, or the number moved to another workspace by a re-onboarding): sending returns `number_unavailable` without inserting a message. Pinned in Task 8 (`number of another workspace is unavailable`).
5. **Messy MCP input** (`addTags: ["  VIP ", "vip", ""]`, 25 tags, a 5000-char text, unknown `stage`): normalized or rejected as a tool result with `isError: true`, nothing partially written. Pinned in Task 3 (`normalizeTags`) and Task 9 (`update_contact rejects 21 tags without writing`).
